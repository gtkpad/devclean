# Requirements: DevClean v2.3 Functional Parity

**Defined:** 2026-10-14  
**Core Value:** O DevClean deve revelar espaço recuperável com precisão e impedir que inventário amplo seja confundido com autorização para apagar dados compartilhados, ativos ou de sessão.

## v2.3 Requirements

### Scan, identity and ownership

- [x] **SCAN-01**: `Scan()` reports every existing target and its occupied bytes without applying `MaxAgeDays` to the root directory mtime.
- [x] **SCAN-02**: A cleaner reports installed when its on-disk target exists, even when its owning executable is absent from `PATH`.
- [x] **SCAN-03**: An empty `ScanPaths` configuration discovers existing `$HOME` roots (`Documents`, `Projects`, `Developer`, `Code`, `Work`, `repos`, `workspace`) in deterministic order.
- [x] **SCAN-04**: Canonical path ownership prevents overlapping cleaners from counting the same descendant bytes twice.

### Review policy and deletion safety

- [x] **POL-01**: A target can carry `ReviewOnly` metadata and an explanatory review reason.
- [x] **POL-02**: `deleter.Coordinator` blocks `ReviewOnly` targets in automatic cleanup and equivalent mutation entry points before hooks or deletion sinks.
- [x] **POL-03**: CLI, TUI and MCP outputs show the `⊙` marker, occupied bytes, eligible bytes and refusal/review reason.
- [x] **POL-04**: DryRun performs no cleaner, trash, hook, scheduler or deletion-history mutation.

### Developer tools and automation

- [x] **DEV-01**: npm cache, npx cache/logs, Corepack, pnpm cache, Puppeteer, Playwright and Cypress caches are discovered by disk presence.
- [x] **DEV-02**: mise, GitHub CLI, pre-commit, Oh My Zsh and zsh completion caches are discovered without touching shell configuration or history.
- [x] **DEV-03**: CoreSimulator caches/temp, iOS/watchOS DeviceSupport and Xcode Archives respect running or unknown Xcode/Simulator process state.

### AI and Electron editors

- [x] **AI-01**: Code, Code Insiders, Cursor, Antigravity, Windsurf, Claude Desktop, OpenCode and Zed cover the specified regenerable Chromium/Electron cache leaves.
- [x] **AI-02**: Editor workspace storage selects only `state.vscdb.backup`; `.obsolete` remains metadata and only directly referenced payloads are candidates.
- [x] **AI-03**: Claude CLI version cleanup preserves the active symlink/version and fails closed on broken or ambiguous links.

### Shared stores and virtual resources

- [x] **STORE-01**: Docker reports total, active, size, reclaimable and detailed JSON metrics when the provider supports them.
- [x] **STORE-02**: OrbStack regenerable caches are separated from VM/data storage in inventory and accounting.
- [x] **STORE-03**: Docker storage, OrbStack data, NuGet packages and pnpm stores are always `ReviewOnly` targets.

### macOS system and user cleaner

- [x] **MAC-01**: User caches, user logs and Trash are inventoried, with Trash requiring an explicit option.
- [x] **MAC-02**: Apple daemon caches, Group Container caches/logs and Handoff use positive allowlists.
- [x] **MAC-03**: Application Support scanning covers only specified regenerable cache/log/Crashpad leaves, including Spotify PersistentCache.
- [x] **MAC-04**: System logs, DiagnosticReports and code-sign clones degrade gracefully on permission or TCC denial and report incomplete coverage.
- [x] **MAC-05**: Process Guard, immutable whitelist, symlink guard and ownership checks prevent cleanup of active applications or protected data.

### Browser cleaner

- [x] **BROW-01**: Chrome, Brave, Arc, Edge, Firefox and Safari are detected by on-disk presence.
- [x] **BROW-02**: Only specified Service Worker caches, GPU/shader/code caches and network caches enter the browser cleanup scope.
- [x] **BROW-03**: Cookies, History, Local Storage, IndexedDB, Login Data and Sessions are never targets.
- [x] **BROW-04**: ScriptCache is inventoried and becomes eligible only after process-guard and MV3/offline acceptance evidence.

### App leftovers and LaunchAgents

- [x] **LEFT-01**: User and system LaunchAgents are read from XML or binary plist files.
- [x] **LEFT-02**: Only an absolute reference to a missing executable is strong stale-item evidence; unreadable, relative, interpreter and PATH-based cases remain unresolved review items.
- [x] **LEFT-03**: App-leftover candidates cross installed bundles with Application Support, Caches and Containers.
- [x] **LEFT-04**: Leftovers and stale LaunchAgents are never removed automatically.

### Validation and acceptance

- [x] **VAL-01**: Every new cleaner has `t.TempDir()` tests with sentinels, permissions, symlink cases and DryRun assertions.
- [x] **VAL-02**: `go test ./...`, altered-package coverage above 85%, and zero-CGO Linux/Darwin builds pass.
- [x] **VAL-03**: macOS acceptance compares DevClean inventory with a read-only benchmark preview and records permissions, processes, TCC/FDA, APFS and omitted items.

## Deferred / future

- Native GUI or Swift integration.
- Background monitoring beyond the existing watcher.
- Automatic deletion of shared stores, VM data, inferred app leftovers or stale LaunchAgents.

## Out of scope

| Feature | Reason |
|---|---|
| Browser session/state deletion | The specification explicitly protects Cookies, History, Local Storage, IndexedDB, Login Data and Sessions. |
| Whole editor or application-support profile deletion | Profiles contain databases, licenses, conversations, uploads and offline state. |
| Unbounded recursive system cleanup | macOS permissions, TCC and protected bundles require positive allowlists. |
| New product integrations outside the five specified fronts | Prevents scope expansion during parity work. |
