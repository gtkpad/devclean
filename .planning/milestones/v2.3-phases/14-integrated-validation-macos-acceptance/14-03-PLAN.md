<threat id="T-14-05" severity="high">
<description>
Inadvertent file deletion or data corruption on the developer's live macOS machine during acceptance test execution if `Clean()` or mutation logic is triggered against real paths.
</description>
<mitigation>
`test/acceptance/macos_test.go` executes DevClean strictly via `engine.Scan(ctx)` in read-only inspection mode. No cleaner `Clean()` or deleter `Delete()` methods are ever invoked during the live acceptance suite.
</mitigation>
</threat>

<threat id="T-14-06" severity="medium">
<description>
Silent data tampering, masking of missing in-scope categories, or inaccurate parity reporting in the generated acceptance receipt.
</description>
<mitigation>
`AssertSafetyInvariants()` executes 4 hard assertions with `t.Fatalf` (D-14), failing immediately if any in-scope category present on disk is missing from DevClean's scan or if duplicate paths are discovered. The dual receipt generation (`.md` and `.json`) preserves raw target data alongside structured analytical sections.
</mitigation>
</threat>
</threat_model>
