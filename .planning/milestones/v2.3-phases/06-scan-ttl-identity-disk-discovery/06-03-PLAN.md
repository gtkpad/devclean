# Plan 06-03: Wave 3 — Canonical Ownership Resolution and Overlapping Target Deduplication

<objective>
Garantir o princípio inviolável de que **cada byte em disco possui exatamente um dono canônico**:
1. Centralizar em `internal/engine/ownership.go` a resolução de posse e eliminação de contagem dupla (`D-01` a `D-04`, `SCAN-04`).
2. Resolver links simbólicos para caminhos físicos reais com `filepath.EvalSymlinks` e desambiguar links circulares graciosamente (`D-02`).
3. Aplicar a regra "Mais Específico Vence" (`D-01`): cleaners dedicados absorvem alvos idênticos e têm seus bytes deduzidos defensivamente de cleaners ancestrais genéricos (`parent.SizeBytes -= child.SizeBytes`), com omissão de alvos subordinados (`D-04`).
4. Integrar o estágio de resolução diretamente em `engine.Collect` (`D-03`), garantindo que CLI, TUI e MCP recebam inventários 100% deduplicados e coerentes.
</objective>

---

<threat_model>
### Modelo de Ameaças & Proteções de Segurança (T-06-05, T-06-06)

#### Trust Boundaries
| Fronteira | Descrição | Nível de Risco |
| :--- | :--- | :--- |
| **Path Canonicalization (`EvalSymlinks`)** | Resolução de caminhos arbitrários no sistema de arquivos | Médio (loops circulares de symlink, DoS por esgotamento de recursos) |
| **Byte Deduction Arithmetic** | Subtração de bytes ocupados entre alvos hierárquicos | Alto (underflow de inteiros, métricas corrompidas de disco) |
| **Central Collector (`engine.Collect`)** | Ponto de agregação único de resultados de scan para a aplicação | Alto (condições de corrida se executado concorrentemente) |

#### STRIDE Threat Register
| Ameaça ID | Categoria STRIDE | Descrição | Mitigação Técnica |
| :--- | :--- | :--- | :--- |
| **T-06-05** | Denial of Service / Crash | Symlinks circulares ou recursivos criados pelo usuário (ex: `link -> .` ou loop A -> B -> A) travando a resolução de caminhos em loop infinito. | **POSIX Loop Detection & Graceful Fallback (D-02):** Utilização exclusiva de `filepath.EvalSymlinks`, que rastreia profundidade e retorna erro `syscall.ELOOP` caso detecte ciclos. Em caso de erro, a rotina faz fallback seguro para `filepath.Clean(path)` sem travar nem entrar em pânico. |
| **T-06-06** | Data Integrity / Double Counting | Divergências de estimativas de tamanho entre cleaners gerando inteiros negativos (`parent.SizeBytes < child.SizeBytes`) ou submissão de ordens de deleção duplicadas para o mesmo diretório. | **Defensive Clamping & Subordinate Omission (D-01, D-04):** A dedução de bytes aplica clamp rigoroso a zero (`if parent.SizeBytes < child.SizeBytes { parent.SizeBytes = 0 } else { parent.SizeBytes -= child.SizeBytes }`). Alvos idênticos absorvidos são completamente omitidos do slice final, impedindo qualquer emissão concorrente de deleção pelo coordenador. |
</threat_model>

---

<must_haves>
### Verdades Invioláveis & Salvaguardas
- **Zero CGO**: Todo o código compila estaticamente com `CGO_ENABLED=0`.
- **Mais Específico Vence (D-01, SCAN-04)**: Cleaners dedicados de ecossistema (`TierDedicated`: node, rust, python, bun, etc.) têm precedência sobre genéricos (`TierGeneric`: macos, system, etc.).
- **Dedução sem Underflow (D-01)**: Quando um alvo filho é detectado dentro de um alvo pai, os bytes de `SizeBytes` e `EligibleBytes` do filho são deduzidos do pai, com clamp a zero para nunca permitir valores negativos.
- **Resolução de Symlinks (D-02)**: Symlinks são resolvidos para caminhos físicos canônicos antes da indexação, unificando referências ao mesmo diretório físico.
- **Centralização Pós-Streaming (D-03)**: A resolução opera atômica e centralizadamente no `internal/engine` após a drenagem dos canais de scan, garantindo ausência total de condições de corrida.
- **Omissão de Alvos Subordinados (D-04)**: Alvos com caminho físico idêntico absorvidos por cleaner de tier superior são omitidos da lista final entregue à UI.
- **Imunidade de Alvos Virtuais**: Alvos com `t.IsVirtual() == true` (Docker, pnpm store, brew) não passam por resolução de filesystem nem dedução de bytes.
</must_haves>

        `parent.EligibleBytes = max(0, parent.EligibleBytes - child.EligibleBytes)`
     4. Alvos virtuais (`t.IsVirtual() == true`) são mantidos integralmente.
     5. Retorna uma nova fatia `[]domain.ScanResult` contendo apenas os alvos não omitidos, preservando a categorização por ecossistema.

<action>
1. Em `internal/engine/engine.go`, atualizar `Collect`:
   ```go
   func Collect(ctx context.Context, ch <-chan domain.ScanResult) []domain.ScanResult {
       var results []domain.ScanResult
       for {
           select {
           case r, ok := <-ch:
               if !ok {
                   return ResolveCanonicalOwnership(results)
               }
               results = append(results, r)
           case <-ctx.Done():
               return ResolveCanonicalOwnership(results)
           }
       }
   }
   ```
